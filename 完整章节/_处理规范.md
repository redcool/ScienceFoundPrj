# 《毒与证》完整章节目录 · 内容与处理规范

> 适用范围：`正文/` 与 `完整章节/` 下的全部文章文件；写正文、合并章节、整理发布时照此执行。
> 约定来源：2026-09-16 与作者三轮对齐后的共识（含一次"误删证据被 revert"的教训）。

## 1. 文章文件里只允许有三类东西

| 类别 | 具体是什么 | 处理 |
|---|---|---|
| **正文** | 大标题（`# 第 X 篇《书名》完整版`）、节标题（`# 主题篇NN：节题`）、正文段落、开篇引言（`> 系列：毒与证 · ……`，属于文章内容）、过渡与收尾句、节间 `---` 分隔 | **保留，一字不改** |
| **证据** | 完整章节文末 `## 证据` 区；正文发布稿各节末尾 `## 资料来源与核实说明`。每条为一行，格式 `1. **事实**：……依据（原始资料）。`；不得含 `层级` 等内部标记 | **保留**——它是读者可查证资产 |
| **编辑元信息** | 篇头概要（`> 番外两节：……`）、合并说明（`> 本文件由已发布小节合并而成……`）、状态指针（`……系列最新状态见 README`） | **删除** |

## 2. 判断口诀

- 读者能直接读、且属于文章内容的 → **正文**，保留。
- 读者查证用的事实＋来源 → **证据**，保留。
- 整理者写给自己的旁白（概要、来源说明、状态指针）→ **元信息**，删除。
- 特别注意：`>` 引用行并不都是同类——各节开头 `> 系列：……` 是**正文引言**，留下；篇头 `> 本文件由……` 是**编辑说明**，删掉。

## 3. 完整章节的标准结构

```
# 第 X 篇《书名》完整版

---

# 主题篇NN：节题
（正文）

# 主题篇NN+1：节题
（正文）

……

## 证据

**第 1 节：节题**
1. **事实**：……依据……。
2. ……

**第 2 节：节题**
1. ……
```

要点：正文一读到尾（节内不夹证据）；证据按节分组收在文末；组内编号从 1 开始。

## 4. 红线与提醒

- **绝不删除证据层**。作者基线提交 `23b99a6 v(0.0.2.2) 一行一证据` 即约定格式；证据内容是读者追查原始资料的路径。
- 完整资料段（含层级/口径等内部信息）：保存在 `正文/` 各发布稿、`docs/` 核验记录（23/30/35/36/37/38/39）与 git 历史；从读者文件里删掉的是展示形式，不是依据本身。
- 处理脚本按目录批量改写时，**必须排除本规范文件**（`完整章节/__处理规范.md`），不得把它当文章改。
