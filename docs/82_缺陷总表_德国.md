# 主笔处理记录（德国篇·广度轮）

## 一、本轮先说工具问题

德国篇的广度扫描，子 agent 连续失败 5 次（"subagent run failed"）。查因结果：

| 测试 | 结果 | 结论 |
|---|---|---|
| 最小任务（读一个文件、回一行） | 通过 | 服务本身没挂 |
| 读 9 个文件、只回行数 | 通过 | 不是文件数量或体量问题 |
| 完整广度扫描、报告不限长 | 失败 5 次 | **问题在输出侧** |
| 同一任务、报告限 120 行 | 通过 | 报告过长导致子 agent 运行失败 |

结论：不是"德国篇太大审不了"，是**审核报告长度超限**。这给技能提了一条新规则候选（见下）。

## 三、本轮规则

- **R9 事实与操作的分界**：写受害过程时，"发生了什么"可以具体，"怎么做成的"不写。判据：把这一句给一个外行，他能不能照着复现步骤；能，就删到只剩结果。
- **R10 审核报告必须限长**：单次审核报告不超过 120 行，超出就分片（按篇或按类型拆成两次）。理由见第一节：报告过长会让审核 agent 直接运行失败，白烧一轮。
- **R11 加害者的词要标来源**："劣等种族""劣等民族"出现在正文里，前面必须带"纳粹的用语／按他们的分类"，否则读者会以为是叙述者的判断。
